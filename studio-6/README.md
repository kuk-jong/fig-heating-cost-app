## 여러 컴퓨터에서 사용
Firebase 연결 전에는 JSON 파일을 내보내 다른 컴퓨터에서 불러옵니다. 브라우저 로컬 저장은 기기별로 독립적입니다.

Firebase 연결 절차:
1. Firebase 프로젝트에 웹 앱을 등록합니다. Authentication에서 Google 로그인 공급자를 활성화하고 승인 도메인에 `kuk-jong.github.io` 및 테스트 시 `localhost`를 추가합니다.
2. Cloud Firestore 데이터베이스와 Cloud Storage를 만들고 이 폴더의 firestore.rules와 storage.rules를 각각 적용합니다. 공개 테스트 규칙을 사용하지 않습니다. Storage 사용에는 프로젝트의 결제 설정이 필요할 수 있습니다.
3. 관리 화면에 Firebase 웹 앱 설정 JSON(apiKey, authDomain, projectId, storageBucket, appId)을 입력하고 로그인합니다. 서비스 계정 비밀키를 입력하지 않습니다.
4. 첫 기기에서 클라우드에 저장하고 다른 기기에서는 같은 프로젝트·계정으로 로그인 후 불러옵니다. 연결만 해서는 기존 자료를 덮어쓰지 않습니다. 동일 계정의 개인 작업공간만 동기화하며 여러 사용자의 공동 편집·공식 사이트 게시 기능은 포함하지 않습니다.
5. 동시 편집 충돌 시 현재 설정을 내보내 백업하고 최신 클라우드 자료를 불러옵니다. 이미지는 변경마다 새 Storage 경로에 저장하므로 이전 이미지 정리는 별도 관리가 필요합니다. 다운로드 URL은 보유자가 접근할 수 있으므로 민감한 사진은 넣지 않습니다.

Firebase 실제 로그인·저장은 프로젝트 설정이 없어 실계정 검증하지 않았습니다. SDK 연결 코드와 규칙을 제공합니다.

## 계산 기준과 제한
원본 integrated-3d/app.js의 22개 지역 base/amp, 아치형 외피(24분할 포물선 길이), 2025-11-01~2026-02-28 120일 일별 모의 최저온도, 14시간 가온, 농사용 전기·경유 발열량과 효율, 최대부하 기반 전기 기본요금, 방풍벽 보정을 이식했습니다. 기본 생산량과 시설투자는 300평=990㎡ 기준 면적 비례입니다. 원본은 생산량과 투자비를 반올림 후 계산하지만 새 버전은 내부에서 연속값을 유지하므로 소액 차이가 납니다. 관행 모드에는 겨울 매출·난방·감가상각을 반영하지 않습니다.

CSV는 `date,temp` 열로 일별 최저온도를 받습니다. 11~2월 월일로 정규화하며 실제 10년 평균을 계산하지 않습니다. 미입력 날짜는 모의값으로 보완합니다. 생육 일정은 예시입니다. 주수는 통로를 차감하지 않은 값입니다. 3D 지붕 표현은 원본처럼 사인 아치이며 계산 외피는 포물선 근사이므로 형태 근사 차이가 있습니다.

겨울 인건비·생산 경영비·금융비용은 원본에 없어 미반영입니다. 회수기간은 관행 대비 추가 현금이익(추가 순이익+감가상각) 기준의 단순 지표입니다. 투자수익률은 추가 순이익/투자비이며 할인율·잔존가치는 미반영입니다. 사진 수준의 작물·장비, 세부 장비 배치 편집은 후속 단계입니다.

인터넷이 없거나 CDN/WebGL을 사용할 수 없으면 3D는 안내문을 표시하며 다른 계산 화면은 작동합니다. 처음 로딩에는 HTTP(S) 정적 서버가 필요합니다.
